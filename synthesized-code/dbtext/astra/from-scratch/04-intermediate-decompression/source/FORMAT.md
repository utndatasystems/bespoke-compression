DBText dictionary-packed codec
================================
One independent archive per original LF-framed input column. The common decoder dispatches by archive magic. Full and arbitrary sorted row queries use identical archives.
Structured formats pack Customer numeric IDs, 9-base genomes, canonical hexadecimal integers, UUID varying fields, and decimal-coordinate tuples. All constants required for reconstruction are in archive headers or the charged decoder binary.
Text columns use per-column phrase dictionaries learned by batched pair merging or exact RePair, followed by shortest-token parsing. An offline encoder-only fitting pass compared several dictionary sizes and both learning methods; fit_settings.h records the chosen method for each input size. Dictionary training and optimal parsing still run inside lab_encode. Symbols have a fixed bit width; dictionary strings are lexicographically prefix-coded, then compressed by a small four-stream canonical Huffman coder implemented here. A frequency-ranked four-bit row-token-count codebook expands to an offset index during lab_open. Text decoding expands dictionary symbols with bounded stores.
URL archives use date and numeric templates, title and prefix dictionaries, plus the same text codec for generic suffixes embedded in the single URL archive. No second full/bulk representation exists.
lab_open creates dictionaries and metadata only. It does not reconstruct or retain a column. lab_rows reconstructs selected bytes and boundaries inside each call, without cached outputs or scans of preceding rows.
The implementation is from scratch. No compression library or downloaded dependency is used. GCC C++17 builds target icelake-server; the decoder uses BMI2, SSSE3/SSE4.1, and AVX-512BW/VL instructions supported by the reported Xeon 5318Y. Platform libc, libstdc++, libgcc and libm are the only dependencies.
The required offline choice fitting cost is recorded in FITTING.json (196.865092516 seconds of resident encode calls). The final lab_encode cost is reported separately and includes dictionary training and optimal parsing with those selected settings. Compilation of the fitted encoder and common decoder is also reported separately. Reconstruction does not use fit_settings.h or FITTING.json: every required dictionary, index and model is in its archive or the charged decoder. Input-specific choices are not intended as a general-purpose codec.
